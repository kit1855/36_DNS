# 36_DNS

dz - описание домашнего задания

Vagrantfile - файл для запуска стэнда

terminal - содержимое терминала при запуске виртуальных машин, и проверки, показывающие выполнение задания

provisioning:

  - empty.newdns.lab - описание зоны для работы bind в режиме сплит-днс, чтоб клиент2 мог получать ответ NXDOMAIN, вместо SERVFAIL или REFUSED на запрос www в зоне newlab.dns. Если в настройках конфига включить рекурсию, то при отсутствии доменного имени в файле зоны, зона будет искаться там где указан поиск по умолчанию. У нас это "точка", т.е. пойдёт в интернет её искать. Там естественно её не найдёт и вернёт ответ SERVFAIL или REFUSED (в зависимости от включенной или выключенной рекурсии). Это можно понимать, что клиент не получил айпи на запрос доменного имени у сервера. По условиям задачи это вроде как подходит, но чтоб звучало красивое NXDOMAIN сделана пустая зона, в которой нет запрашиваемого имени. Т.е. зону видит, а имя нет.

  - master-named.conf - конфиг bind для ВМ ns01, копируется внутрь ВМ и переименовывается в named.conf. В нём указано что данный днс-сервер имеет тип master и то, какие доменные имена из каких зон каким клиентам отдавать.

  - named.dns.lab - описание зоны dns.lab с web1 и web2.

  - named.dns.lab.client - описание зоны для работы bind в режиме сплит-днс. Т.к. в зоне dns.lab у нас есть и web1 и web2, а bind не умеет из одного файла отдавать что-то одно, то единственный способ это сделать- создать ещё один файл описывающий зону, где нет web2. Когда клиент1 сделает запрос, то в блоке view увидит указание отдать ту зону dns.lab, в которой нет web2.

  - named.newdns.lab - описание зоны newdns.lab с www.

  - named.zonetransfer.key - ключ, добавляется в конфигурационные файлы серверов через include. ВМ ns01 в роли мастера будет отдавать зоны слэйву ВМ ns02, только при совпадении ключа. Ключей три. Один ключ для трансфера полных зон, которые будут одинаково отдаваться двум клиентам. Другие два ключа для того, чтоб можно было специально отдавать урезанную зону днс.лаб и зону пустышку ньюлаб.днс. 

  - slave-named.conf - конфиг для bind на ВМ ns02, копируется внутрь ВМ и переименовывается в named.conf. В нём указано, что данный днс-сервер имеет тип slave и кто для него является мастером.

Трансфер зон с ВМ ns01 на ВМ ns02 настроен. Ни одна зона на ВМ ns02 не появляется в результате работы провижинга при поднятии ВМ. При проверках правильности настроенных серверов делаются проверки конфигов, проверки на корректность скопированных зон на ВМ нс01 и зон созданных путём трансфера с ВМ ns01 на ВМ ns02. На ВМ ns02 дополнительно проверяется наличие файлов, созданных в результате трансфера зон. На обоих серверах делаются проверки, что зоны отдаются. На клиентах проверяются запросы к обоим серверам со всеми доменными именами (web1, web2, www) во всех зонах (dns.lab и newdns.lab).

Выбрана версия линукса - альмалинукс. Вагрантфайл собран со своего шаблона, схема рабочая, не стал ничего менять в стиле, просто внёс изменения для соответствия этому заданию.
