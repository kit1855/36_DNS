# 36_DNS

dz - описание домашнего задания

Vagrantfile - файл для запуска стэнда

terminal - содержимое терминала при запуске виртуальных машин, и проверки, показывающие выполнение задания

provisioning:
  - master-named.conf - конфиг bind для ВМ ns01, копируется внутрь ВМ и переименовывается в named.conf. В нём указано что данный днс-сервер имеет тип master и то, какие доменные имена из каких зон каким клиентам отдавать.

  - named.dns.lab - описание зоны dns.lab с web1 и web2.

  - named.dns.lab.client - описание зоны для работы bind на ВМ ns01 в режиме сплит-днс. Т.к. в зоне dns.lab у нас есть и web1 и web2, а bind не умеет из одного файла отдавать что-то одно, то единственный способ это сделать- создать ещё один файл описывающий зону, где нет web2. Когда клиент1 сделает запрос, то в блоке view увидит указание отдать ту зону dns.lab, в которой нет web2.

  - named.newdns.lab - описание зоны newdns.lab.

  - named.zonetransfer.key - ключ, добавляется в конфигурационные файлы серверов через include. ВМ ns01 в роли мастера будет отдавать зоны слэйву ВМ ns02, только при совпадении ключа.

  - slave-named.conf - конфиг для bind на ВМ ns02, копируется внутрь ВМ и переименовывается в named.conf. В нём указано, что он имеет тип slave и кто для него является мастером.
